# Project pages — design

Mock, detailed **Project** pages for CodeVault, built to compare three distinct
visual/structural treatments of the same idea. The goal is exploration: the user
picks a favorite direction. All three stay inside the design system
(`docs/design-system.md`, `docs/design-rules.md`) and the CodeVault voice
(`docs/overview.md`).

## Principle

Not one template rendered three times — **three genuinely different page
treatments**, one per project. What differs is composition, rhythm, and
emphasis, not the token system. Every page uses ivory/slate/olive tokens, the
`text-display-*` / `text-paragraph-*` / `text-detail-xs` scale, one serif-italic
accent word per heading, shared motion variants, dark mode, and reduced motion.

## Projects → styles

| Slug | Project | Style | Character |
| --- | --- | --- | --- |
| `orbit` | Browser game about keeping satellites from colliding | **Mission dossier** | NASA-adjacent, technical/editorial. Mono eyebrows, numbered sections, a telemetry facts rail, status chip, tabular numbers, hairlines. |
| `plant-pi` | Teaching a Raspberry Pi to water plants | **Field journal** | Warm, log-forward. The dated project log is the spine. Big serif-italic accent, oat/ivory warmth, generous measure, photo-placeholder blocks. Honest about what broke. |
| `git-story` | CLI that turns a git log into a story | **Spec sheet / README** | Developer, terminal-forward. Terminal-style hero with install snippet, spec table, `$`-prefixed command blocks, mono-forward. |

## Routing

- `/projects` — light index listing all three (target for the dropdown's
  "All projects").
- `/projects/orbit`, `/projects/plant-pi`, `/projects/git-story` — the three
  styled detail pages.
- `/projects/plant-pi/log` — one real subpage (full project log), to demonstrate
  the subpage pattern. Orbit and git-story keep their logs inline.

Routes are file-based (`src/routes/`), SSR. `routeTree.gen.ts` is regenerated by
the router plugin — never hand-edited.

## Content model (per project)

Each project carries: title, one-line summary, status (Shipped / In progress /
Paused), field, dates (started, and shipped/updated), people/crew, tech stack,
repo + demo/artifact links, license; the **Trial → Experience → Adjustment →
Result** loop filled with the project's real story; a dated **project log**; a
short **notes / write-up**; and a "next project" pointer.

## Data & wiring

- New `src/core/config/projects.ts` — one rich, typed `Project[]` holding all
  structured content (keeps content config-driven per `docs/code-rules.md`;
  avoids further bloating `site.ts`). A `getProject(slug)` helper and a
  `nextProject(slug)` helper. Exposed shared subtypes for log entries, loop
  steps, facts.
- The three detail components render the same `Project` model in three layouts.
  Bespoke *structure* lives in the components; user-facing *strings* live in
  config.
- **Homepage** (`latest-releases.tsx` / `site.ts`): point the existing
  `releases` cards at the real routes; internal links use the router `Link`, not
  a raw `<a href>`.
- **Navbar dropdown + Footer** (`site.ts`): replace `#releases` hash links under
  "Projects" with the real routes. A nav link may now be internal (`/projects…`)
  or a hash (`#…`); the nav renders `Link` for internal paths and `<a>` for hash
  anchors.

## Shared building blocks

Small presentational primitives reused across the three styles where it doesn't
flatten their distinctiveness:

- `StatusChip` — status pill (olive for shipped/healthy, muted for paused).
- A page chrome wrapper: `Navbar` + `main` + `Footer`, matching the homepage
  shell, so project pages sit in the same frame.

Each detail page is its own component under
`src/components/projects/<slug>/` (or a single file if small), imported by its
route. Keep files focused per the code rules.

## Definition of done

Held to `docs/design-rules.md`: tokens only (no raw hex / raw sizes), mobile-up
responsive, light **and** dark mode, motion reuses shared variants and respects
`useReducedMotion()`, keyboard-navigable with visible focus and correct
ARIA/semantics, copy in the CodeVault voice. Verified in the running app
(typecheck + lint + observe), not just compiled.

## Out of scope

Real project data/CMS, real repos/demos (links are plausible placeholders),
search/filtering on the index, pagination, per-project subpages beyond the one
demo log.
